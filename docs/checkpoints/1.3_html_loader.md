# Checkpoint 1.3 — HTML / Web Loader

## What we built
- `HTMLLoader` accepting URL or local file input
- **Two extraction strategies** behind one loader: `trafilatura` (default), `bs4` (escape hatch), `both` (A/B eval)
- Metadata capture: title, author, date, language (via trafilatura's built-in extractor)
- Auto-detection of URL vs file source
- User-Agent header (many sites 403 the default `python-requests/2.x`)

## Core concepts

### 1. HTML is 90% chrome, 10% content
A typical web page is nav bars, footers, ads, cookie banners, "related articles," comment sections — and only ~10% actual content. A naive extractor gives you noise *and* content; retrieval then embeds the noise, and you spend weeks wondering why RAG returns cookie policies.

### 2. Two extractors, two philosophies
| Library | Approach | When to use |
|---------|----------|-------------|
| **BeautifulSoup** | You write CSS/tag selectors | Known structure, one site, full control |
| **Trafilatura** | ML-heuristic boilerplate remover | Arbitrary URLs, unknown structure, out-of-the-box |

Trafilatura is what LlamaIndex, Haystack, and most production crawlers use for "reader mode" extraction. It was purpose-built for research corpora and consistently ranks #1 on boilerplate-removal benchmarks.

### 3. Aggressive CSS selectors over-strip
Our first bs4 implementation used selectors like `[class*='navigation']` to strip chrome — worked well on typical blogs, but on Wikipedia stripped *everything* (Wikipedia's table of contents is inside `nav` elements). We removed those selectors, accepted that bs4 is noisier by default, and let trafilatura do the heavy lifting.

Lesson: don't roll your own boilerplate remover. Use trafilatura for arbitrary URLs, use bs4 with hand-crafted selectors only when you know the specific site.

### 4. Measured boilerplate reduction
On the Wikipedia RAG article:
- bs4: 22,884 chars
- trafilatura: 15,057 chars
- **Delta: 7,827 chars — 34% noise removed**

And it's not just noise — bs4's output fragmented every hyperlink and citation onto its own line (`get_text(separator="\n")`). Trafilatura preserves paragraph flow. That structural preservation dramatically improves downstream chunking quality.

### 5. Metadata via trafilatura's built-in extractor
Trafilatura ships an `extract_metadata()` function that pulls title, author, date, language from `<meta>` tags, OpenGraph, JSON-LD, and other common patterns. Free structured metadata for every page — invaluable for filtering and citations.

## Why the design choices

- **Trafilatura as the default**: production-standard, purpose-built, ML-trained
- **BS4 as the escape hatch**: sites you *know* the structure of get better results with hand-tuned selectors
- **`strategy='both'` for A/B**: eval-driven; you measure the delta rather than assume the default is best
- **User-Agent header**: many sites (Wikipedia included) return 403 to the default requests UA
- **Content-length threshold (`min_chars=100`)**: HTML frequently has partial-page failures; skipping tiny extractions avoids polluting the index

## Interview flashcards

1. **Q:** Why not just `BeautifulSoup(html).get_text()`?
   **A:** You keep 90% chrome. Cookie banners, nav bars, footers all get embedded, poisoning retrieval. Trafilatura (or Readability, or trafilatura's peers) uses ML-heuristic tree analysis to distinguish content from chrome. On a moderately clean site like Wikipedia, it removes ~34% noise.

2. **Q:** When would you use BS4 over trafilatura?
   **A:** When you're scraping one specific site whose structure you know. Hand-crafted CSS selectors give you full control — extract exactly the `.article-body` div, ignore everything else. Trafilatura is for "any URL, extract the main article." BS4 is for "this specific site, exactly this element."

3. **Q:** Why does trafilatura beat naive tag-stripping on CMS sites?
   **A:** CMS sites (Wikipedia, WordPress) use semantic tags for chrome — `<nav>` contains the table of contents, `<aside>` contains related content. Blindly stripping those tags kills content. Trafilatura uses text density, link ratios, and boilerplate patterns rather than tag identity — much more robust.

4. **Q:** Your HTML loader takes both URLs and local files. Why?
   **A:** Two use cases. URL: crawl fresh content from the web. Local file: reproducible tests (fetch once, save `.html`, re-run without hitting the network) and offline processing of previously-downloaded content. Same loader, two entry points.

5. **Q:** What's the failure mode if a page requires JavaScript to render?
   **A:** `requests.get()` returns the static HTML skeleton, not the JS-rendered content. Trafilatura will extract almost nothing meaningful. Fix: use a headless browser (Playwright, Selenium) to render first, then extract. That's an M12 upgrade path.

*"How do you handle scraping arbitrary websites for a RAG corpus?"*

Then I run trafilatura by default — it's an ML-heuristic boilerplate remover that consistently ranks #1 on content-extraction benchmarks. It handles multi-column layouts, ignores nav/footer/cookie banners, and preserves paragraph flow. There's also a BS4 fallback for cases where I know a specific site's structure well enough to write custom CSS selectors, and a `strategy='both'` mode that runs both extractors so I can A/B them through the eval harness.
