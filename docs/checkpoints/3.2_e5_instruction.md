# Checkpoint 3.2 — E5 + InstructionEmbedder

## What we built
- `E5Embedder` — both queries AND passages get prefixes (`"query: "` / `"passage: "`)
- `InstructionEmbedder` — configurable task instruction, clean sentence-transformers implementation (replaced broken `InstructorEmbedding` library)
- Empirical comparison: BGE-small gap=0.257, E5 gap=0.093, InstructionBGEb gap=0.124

## Core concepts

### 1. The three asymmetric embedding families

| Model | Query prefix | Passage prefix | Key property |
|-------|-------------|----------------|--------------|
| BGE | `"Represent this sentence for searching relevant passages: "` | None | One-sided asymmetry |
| E5 | `"query: "` | `"passage: "` | Both sides prefixed |
| Instructor/Instruction | `"Represent the {domain} {text_type} for retrieval: "` | Same structure | User-defined |

All three were trained with contrastive objectives on large retrieval datasets. The difference is in how they encode the semantic role of the text being embedded.

### 2. E5's dual-prefix — what it changes
BGE tells the model what the query is for (finding passages) but not what the passage is. E5 explicitly signals the role of both sides. During training, the model learned that `"passage: ..."` and `"query: ..."` text should relate in a specific geometric way — one is the answer space, one is the question space.

Effect: E5's embedding space is more explicitly separated between query and passage subspaces. Scores are compressed (0.72–0.85 for E5 vs 0.36–0.64 for BGE on our 3 test passages), but ranking is preserved with less margin.

### 3. Score compression is a characteristic, not a defect
BGE-small: BM25 score=0.6427, next=0.3862 — gap=0.257
E5-small:  BM25 score=0.8524, next=0.7594 — gap=0.093

E5 has all scores in a narrow high range. The correct chunk still wins, but by less margin. This matters for reranking (M6): a tighter score distribution means the initial ranking carries less signal — the reranker has to work harder to separate candidates.

### 4. The InstructorEmbedding library is unmaintained
`InstructorEmbedding` — last commit 2023 — breaks on current `sentence-transformers` because `_text_length()` was renamed to `_input_length()` with a different signature. The monkey-patch `SentenceTransformer._text_length = SentenceTransformer._input_length` fixed the attribute lookup but not the signature mismatch.

**The right fix:** reimplement the value proposition directly. Instructor's core insight is "prepend a task instruction." This works with any sentence-transformers model:

```python
prefixed = f"{instruction}{text}"
vector = model.encode([prefixed], normalize_embeddings=True)[0]
```

Our `InstructionEmbedder` does exactly this — configurable instruction, clean dependency, no monkey-patching.

### 5. Library deprecation is part of production engineering
When a dependency breaks, you have three options:
1. Pin to a compatible older version — breaks other dependencies
2. Fork and fix — maintenance burden
3. Reimplement the value proposition — clean, maintainable

Option 3 is the right call for a 50-line abstraction over a broken library. The "value proposition" of Instructor is one line of Python. The rest is infrastructure we already have.

## Interview flashcards

1. **Q:** What's the difference between E5 and BGE?
   **A:** E5 prefixes both queries (`"query: "`) and passages (`"passage: "`). BGE only prefixes queries. E5's dual-prefix creates a more explicitly asymmetric embedding space — both sides signal their role during encoding. In practice, E5 produces higher absolute cosine scores with tighter inter-document separation, while BGE produces lower scores with wider gaps.

2. **Q:** E5 scores are compressed into 0.72–0.85 vs BGE's 0.36–0.64. Which is better?
   **A:** Neither — they're different. High compressed scores mean high absolute similarity but less margin between candidates. Wide spread means more separation but lower absolute values. For retrieval accuracy, both rank correctly. For downstream reranking, BGE's wider spread gives rerankers more signal. For threshold-based filtering (return only chunks above 0.7), E5 returns more candidates.

3. **Q:** The InstructorEmbedding library was broken. What was your fix?
   **A:** Reimplemented the value proposition directly. Instructor's insight is "prepend a task instruction to the text before encoding." That's one line: `prefixed = f'{instruction}{text}'`. Using sentence-transformers with this prefix is functionally equivalent, has no broken dependency, and needs no pinned versions. The `InstructorEmbedder` class is now `InstructionEmbedder` wrapping BGE-base.

4. **Q:** What instruction would you write for a legal document corpus?
   **A:** Query: `"Represent the legal question for retrieving relevant case law: "`. Passage: `"Represent the legal document for retrieval: "`. Domain specificity matters — "legal question" vs "question" tells the model to weight legal terminology more heavily. The closer the instruction matches your domain, the better the embedding space alignment.

5. **Q:** When would you choose E5 over BGE?
   **A:** When you need higher absolute similarity scores for threshold-based filtering, or when your corpus has many paraphrased passages that BGE's one-sided asymmetry misses. In our benchmark, E5 closed BGE-small's one recall failure (hybrid retrieval query) — that failure was worth 3.2x the compute cost in our production scenario.

## Code walkthrough prompt

*"How do your E5 and Instruction embedders differ from BGE?"*

> "E5 adds a `'passage: '` prefix to every document at embed time, in addition to the `'query: '` prefix on queries. This dual-side signaling was in E5's training — both query and passage sides learned to represent their role explicitly. The practical effect is compressed but uniformly high scores. For InstructionEmbedder, I originally tried the `InstructorEmbedding` library but it was broken on current sentence-transformers — the `_text_length` method signature changed. Rather than monkey-patching a 2023-vintage unmaintained library, I reimplemented the value proposition: Instructor's insight is just prepending a user-defined instruction string before encoding. So `InstructionEmbedder` wraps any sentence-transformers model and prepends `embed_instruction` to passages and `query_instruction` to queries. Same semantic effect, clean dependency, no version pins. Both E5 and InstructionEmbedder inherit the same three-method interface — `embed()`, `embed_query()`, `embed_numpy()` — so the benchmark and retriever code are identical for all three."
