## Core concepts

### 1. The silent truncation problem
Every transformer-based embedder has a max sequence length. Text exceeding it gets **silently truncated** — no error, no warning, just missing content in the embedding.

```
BGE-small: 512 tokens ≈ 2000 chars
E5-small:  512 tokens ≈ 2000 chars
Jina-v3:   8192 tokens ≈ 32000 chars
```

For chunks under 400 chars (which is most of our M2 portfolio), truncation never happens. For parent chunks (1500+ chars), legal documents, or whole-document embedding, BGE/E5 silently lose 25-80% of the content.

**Why this is catastrophic:** the embedding of a truncated chunk represents only the beginning of the document. A fact that appears in paragraph 5 (past the truncation boundary) is simply not in the embedding — retrieval cannot find it.

### 2. When Jina is the right tool
- **Parent chunks from ParentChildChunker** (1500 chars avg) — BGE truncates at ~2000 chars, but the safety margin is thin
- **Long-form document embedding** — embedding whole sections of research papers
- **Legal/financial documents** — key facts often appear deep in the text
- **max_chunk_size > 1000 chars in SemanticChunker** — large topic-coherent sections

For small chunks (<400 chars), BGE-small is faster with comparable quality. The crossover point is around 400-500 chars average chunk size.

### 3. trust_remote_code is a production risk
Jina models use `trust_remote_code=True` — they download and execute custom Python code from HuggingFace at load time. This code broke on two consecutive major releases:
- Jina v2: `from transformers.onnx import OnnxConfig` — module removed in recent transformers
- Jina v3: `'XLMRobertaLoRA' object has no attribute 'all_tied_weights_keys'` — renamed attribute

**Production implications:**
1. Pin `revision` to a specific commit hash: `AutoModel.from_pretrained(model, revision="abc123")`
2. Test model loading in CI before every transformers upgrade
3. Maintain a local cache of verified working model files
4. Have a fallback embedder (BGE) ready when `trust_remote_code` breaks

### 4. The stub pattern
When a library is broken and the fix is non-trivial:
```python
class JinaEmbedder:
    def __init__(self, *args, **kwargs):
        raise NotImplementedError(
            "JinaEmbedder is currently incompatible with installed "
            "transformers version. See embedders/jina_embedder.py for details."
        )
```

This is better than:
- Removing the file (concept lost, upgrade path unclear)
- Silent failure (breaks downstream code mysteriously)
- Keeping broken code (misleads future readers)

The stub documents the intent, raises clearly, and points to resolution steps.

### 5. Long-context is an active research area
Beyond Jina, the long-context embedding landscape includes:
- **Voyage-3**: 32K context, strong MTEB scores, API-only
- **Nomic-embed-text-v1.5**: 8192 context, open source, Matryoshka dims
- **GTE-Qwen2**: 32K context, strong multilingual

The right answer changes frequently. The architectural lesson — "know your model's context window and verify chunks don't exceed it" — is stable.

## Interview flashcards

1. **Q:** What is silent truncation and why is it dangerous?
   **A:** When text exceeds an embedder's max sequence length, the excess is silently dropped — no error, no warning. The embedding represents only the beginning of the text. For a 2000-char chunk with a 512-token model, you lose everything after ~1500 chars. Facts appearing late in a document become completely unretrievable. It's dangerous because there's no signal that retrieval is failing due to truncation rather than relevance.

2. **Q:** How would you detect silent truncation in a production system?
   **A:** Three ways. First, track the distribution of chunk sizes vs the model's token limit — flag chunks exceeding 80% of the limit. Second, compare embedding similarity between a full text and its first 512 tokens vs its last 512 tokens — a truncated model will score these differently than expected. Third, test with a gold query whose relevant passage appears late in a document — if retrieval fails only for deep passages, truncation is likely.

3. **Q:** What is trust_remote_code and when should you use it?
   **A:** It allows the model to download and execute custom Python code from HuggingFace at load time — the model repo includes its own architecture/config files that override transformers defaults. Use it only for models from trusted providers (Jina, MosaicML) when you've reviewed the remote code or pinned to a specific commit hash. Never use it in production without pinning the revision — a model maintainer updating their remote code can break your deployment at the next transformers upgrade.

4. **Q:** For what use case would you definitely choose Jina over BGE?
   **A:** Whole-document retrieval where documents are 5000+ chars. Legal contracts, research papers, financial filings — documents where the answer often appears deep in the text. BGE at 512 tokens would embed only the first 2000 chars of a 20-page contract. Jina at 8192 tokens embeds up to 32,000 chars. For these documents, Jina is strictly better — BGE's truncation makes it architecturally incorrect.

5. **Q:** The Jina library broke on two consecutive transformers versions. What does that tell you about the model ecosystem?
   **A:** Models using trust_remote_code are tightly coupled to a specific transformers version. The model maintainer and the transformers team independently make breaking changes. Your production system is at the intersection of both release cadences. Mitigation: pin transformers version in requirements.txt, test model loading in CI on every pip upgrade, maintain a fallback embedder, and review model changelogs before upgrading.

## Code walkthrough prompt

*"You stubbed the Jina embedder. Why not just remove it?"*

> "The stub preserves the architectural intent and the upgrade path. Removing the file loses the concept — a future engineer (or me in 6 months) won't know Jina was considered, why it was selected, or how to wire it when it's fixed. Silent removal also breaks any config that references 'jina' as an embedder name. The stub raises a clear `NotImplementedError` with the specific failure reason and a link to the upstream issue, so the next person knows exactly what to fix and why it broke. The module docstring documents the workaround: `SentenceTransformer("jinaai/jina-embeddings-v3", trust_remote_code=True)` with a pinned revision. That's the correct production pattern regardless — never use `trust_remote_code` without pinning."
